FARTOVIY — Angular-каталог

Запуск
  Node.js 22.18+
  npm ci
  npm start
  http://localhost:4200

Реализовано восемь компонентов
  1. Каталог: список всех товаров.
  2. Карточка товара: фото, название, цена и переход к товару.
  3. Страница товара: описание, выбор размера и добавление в корзину.
  4. Корзина: количество, удаление, сумма и сохранение в браузере.
  5. Распознавание: фото или снимок с камеры, рамки и список найденных объектов.
  6. Оформление заказа: контакты, проверка состава и суммы, сохранение.
  7. Подтверждение: номер, сохранённый состав, контакты и копирование заказа.
  8. История заказов: список заказов этого браузера.

Локальная база товаров
  Используется IndexedDB: база fartoviy-products, версия 2, хранилища products и orders.
  Ключ товара: id; индекс по category. Дополнительный сервер не нужен.
  При первом открытии база заполняется восемью товарами из catalog.ts.
  Затем каталог, страница товара и цены корзины читаются из IndexedDB.
  Изменения и удаления сохраняются между перезагрузками и повторными визитами.
  Пустая база остаётся пустой: повторное открытие не восстанавливает удалённые товары.
  Изменение catalog.ts после создания базы не перезаписывает локальные записи.
  Для будущего обновления схемы нужно повысить версию и добавить миграцию в open().
  ProductDatabase предоставляет list(), get(id), save(product), remove(id), close().
  save() добавляет или обновляет товар после проверки обязательных полей и цены.
  Методы записи завершаются только после успешного commit транзакции.
  Интерфейс редактирования товаров пока не добавлен; подготовлен слой хранения.
  Фотографии остаются файлами сайта; в базе хранятся пути к ним.
  При ошибке доступа показывается сообщение и кнопка повтора, без удаления данных.
  Сохранённая корзина проверяется после загрузки базы; удалённые товары исключаются.
  Посмотреть данные: DevTools -> Application -> IndexedDB -> fartoviy-products.
  У каждого браузера и адреса сайта своя база; между устройствами синхронизации нет.
  Очистка данных сайта удаляет базу. IndexedDB сам по себе не кеширует файлы сайта.

Оформление заказов
  Корзина -> Оформить заказ -> Контакты и состав -> Сохранить заказ -> Подтверждение.
  В форме обязательны имя и email; телефон и комментарий необязательны.
  Перед записью цены и размеры повторно проверяются по актуальным товарам в базе.
  При изменении каталога нужно проверить новый состав/сумму и подтвердить ещё раз.
  Сохраняется снимок: названия, размеры, количества, цены, сумма, контакты и дата.
  Изменение или удаление товаров не меняет уже сохранённые заказы.
  База обновляется с v1 до v2 без пересоздания и перезаписи товаров.
  ProductDatabase: createOrder(draft), getOrder(id), listOrders().
  Проверка товаров и запись заказа выполняются в одной транзакции IndexedDB.
  Корзина очищается только после успешного commit заказа; при ошибке остаётся.
  Токен попытки сохраняется в fartoviy-checkout-attempt и защищает от повторной записи.
  Новое изменение корзины создаёт новую попытку, поэтому одинаковые новые заказы разрешены.
  История: #/orders. Подтверждение: #/orders/<id>. Оформление: #/checkout.
  На подтверждении можно скопировать текст заказа и вручную передать продавцу.
  Заказы хранятся только в этом браузере и не отправляются продавцу автоматически.
  Статус «сохранён» не означает принятие продавцом или оплату; доставки и оплаты нет.
  Контактные данные хранятся вместе с заказом локально; очистка данных сайта удаляет их.
  Логика проверки и расчёта суммы: src/app/core/order.ts.

Язык интерфейса
  При первом посещении выбирается первый поддерживаемый язык из настроек браузера.
  Поддерживаются английский (en), русский (ru) и украинский (uk), включая ru-RU/uk-UA.
  Если подходящего языка нет, используется английский.
  Ручной выбор EN/RU/УКР сохраняется и имеет приоритет при следующих посещениях.
  Автоматически выбранный язык не записывается как ручное предпочтение.
  Старое значение fartoviy-language игнорируется: оно сохраняло и автоматический RU.
  Проверка выбора языка и переводов: npm test.

Распознавание в браузере
  Откройте вкладку Recognition / Распознавание / Розпізнавання.
  Загрузите JPG, PNG или WebP до 20 МБ (до 40 мегапикселей),
  сделайте снимок с камеры или нажмите «Попробовать пример», затем «Распознать».
  Адрес после публикации: https://qwer605.github.io/FartoviyWeb/#/recognize
  Фото и кадры обрабатываются локально и не отправляются на сервер.
  Камера требует HTTPS либо localhost и разрешение пользователя.
  После снимка, закрытия камеры или ухода со страницы видеопоток останавливается.
  Модель YOLO26s-seg (41,9 МБ) и ONNX Runtime Web WASM загружаются
  с того же сайта по запросу; отдельного backend и новых npm-зависимостей нет.
  Вычисления выполняются в Web Worker на CPU без требований COOP/COEP.
  Выводятся полупрозрачные маски объектов вместо прямоугольных рамок.
  Режим «Все объекты»: порог по умолчанию 25%, максимум 30 масок.
  Порог можно изменять от 10% до 80%; изменение сбрасывает прежний результат.
  Поддерживаются 80 классов COCO, включая людей, рюкзаки и сумки.
  Это не поиск конкретных товаров: для одежды, обуви и SKU нужна другая модель.
  Источник, версия, SHA256 и лицензия модели: public/models/README.txt.
  Обработка изображения и координат: src/app/core/vision.ts.
  Загрузка и запуск модели: src/app/core/detector.ts, detector.worker.ts.

Поиск шахматного узора внутри масок
  По умолчанию включён режим «Сумки и шахматный узор».
  YOLO26s-seg -> маски-кандидаты -> проверка светлых/тёмных клеток внутри маски.
  Порог кандидатов по умолчанию 10%; это уверенность исходного класса YOLO,
  а не вероятность узнавания конкретной сумки.
  Проверяются классы handbag, backpack, suitcase и tie: на боковом ракурсе
  исходная модель иногда путает сумку с галстуком, но маска покрывает её корпус.
  Исходный класс сохраняется и показывается; tie не переименовывается в handbag.
  Дублирующие области с IoU > 0,8 исключаются; проверяется максимум 8 кандидатов.
  Проверка текстуры: разные масштабы, пропорции клеток и повороты; проверка
  повторяемости и направлений градиента помогает отличать клетки от полос.
  Окна анализа находятся внутри маски; клетчатый фон вне маски не считается.
  Маска кандидата синяя, найденные участки текстуры оранжевые.
  Для совпадения нужно не менее 300 пикселей текстуры и 2% площади маски
  на изображении анализа с длинной стороной до 512 пикселей.
  Доля текстуры — площадь найденных участков / площадь маски, не оценка подлинности.
  Совпадение не подтверждает бренд, конкретную модель или принадлежность к сумкам.
  Похожие текстуры могут давать ложные совпадения; отсутствие маски YOLO означает
  отсутствие кандидата для второго этапа. Произвольные ракурсы не гарантируются.
  На трёх предоставленных фото локально найдены совпадения: фронт и два боковых вида.
  Эти фото использовались при разработке; независимая проверка на новых снимках нужна.
  Фотографии и локальные отчёты из .angular/recognition-experiments не публикуются.
  Логика: src/app/core/checker-texture.ts и bag-pattern.ts; выполняется в том же Worker.

Проверки
  npm test — переводы, выбор языка, IndexedDB, миграция и расчёт заказов,
  RGB-вход, маски, поиск клеток, проверка фона вне маски и SHA256 модели.
  tsx используется только для запуска TS-тестов.
  npm run build -- --base-href /FartoviyWeb/
  npx playwright install chromium
  npm run test:e2e — оформление/история заказов, сохранение каталога/корзины, реальный ONNX/WASM,
  камера, ошибки и мобильная вёрстка.
  Для установленного Edge в PowerShell: $env:PLAYWRIGHT_CHANNEL='msedge'
  Браузерные тесты используют production-сборку dist/ и путь /FartoviyWeb/.

Глобального CSS нет. Баннеры, иконки, избранное и демооплата не реализованы.
Цены демонстрационные, в условных единицах; доставки нет.

Сборка
  npm run build
  Результат: dist/index.html и соседние файлы.
  При сборке dist/ пересоздаётся; редактировать нужно src/.

CI/CD FE в GitHub Actions и GitHub Pages
  Workflow: .github/workflows/fe-ci.yml.
  Запускается при push в quality/main и при создании или обновлении PR в main.
  Устанавливает Node.js 22, выполняет npm ci, npm test и production-сборку npm run build.
  Затем запускает браузерные проверки распознавания в Chromium.
  Собирает приложение с base href /FartoviyWeb/ для адреса репозитория.
  PR и push в quality только проверяют сборку.
  Каждый push в main, включая merge PR quality -> main, публикует dist/ в Pages.
  При ошибке сборки публикация не запускается.
  Адрес FE: https://qwer605.github.io/FartoviyWeb/
  Результат виден во вкладке Actions и в проверках PR: FE pipeline / Production build.
  Первичная настройка: Settings -> Pages -> Build and deployment -> GitHub Actions.
  Для ручного повторного запуска выберите main во вкладке Actions -> FE pipeline.
  Workflow использует встроенный GITHUB_TOKEN; отдельные секреты не нужны.
  Для запрета merge при ошибке сборки добавьте Production build в required checks
  правила защиты ветки main в настройках GitHub.
